# Checkout

## `GET /checkout_info` (`getCheckoutInfo`)

- **silent**, auth/-: GET /checkout_info is called with the app token alone, without the secret and without parameters → Accepted; the checkout settings returned are those of the store the app token belongs to. **Do:** Call GET /checkout_info with `Authorization: Bearer {jwt}` using the app token of the store whose settings you need. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/checkoutinfo/request/get.md`; docs `content/ja/docs/api/checkoutinfo/overview.md`; `getCheckoutInfo.1`)*
- **silent**, auth/values: Reading `mode` in the checkout info → `live` or `test` reflects the mode of the app token used for the call. **Do:** Use a live-mode app token when you need the live checkout settings. *(spec `spec/openapi.yaml`; `getCheckoutInfo.2`)*
- **silent**, -/values: The store has not customised its widget theme colours; the definition says each colour resolves to the platform default shown in its examples (e.g. main_background #FFFFFF), but the checkout-info overview page lists other defaults (e.g. main_background #fafafa) → Each theme colour is returned with a default value and is never null. **Do:** Use the colour values returned instead of hard-coded defaults, since the sources disagree on the defaults. **Conflict:** The definition (CheckoutThemeColors) and content/ja/docs/api/checkoutinfo/overview.md give different default colours; not tested, so the record states both. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/checkoutinfo/overview.md`; `getCheckoutInfo.3`)*
- **silent**, account-config/values: The store has no recurring-charge CVV confirmation setting → `recurring_card_charge_cvv_confirmation.enabled` is returned as false. **Do:** Treat enabled false as no CVV re-confirmation for recurring card charges. *(spec `spec/openapi.yaml`; `getCheckoutInfo.4`)*
