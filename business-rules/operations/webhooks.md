# Webhooks

## `GET /stores/{storeId}/webhooks` (`listWebhooks`)

- **loud**, auth/-: The request is sent with the app token alone, without its secret (the docs list the secret as required for these calls); tested on GET /me only → 401 Empty body (tested on GET /me). **Do:** Send these calls from your server with `Authorization: Bearer {secret}.{jwt}`, never with the bare app token. Also: `getCurrentMerchant`, `getStore`, `listStores`, `createCustomerId`, `listTransactionHistory`, `listStoreTransactionHistory`, `createWebhook`, `getWebhook`, `updateWebhook`, `createDirectDebitBankAccount`, `updateDirectDebitBankAccount`. *(docs `content/ja/docs/api/merchant/request/get.md`; docs `content/ja/docs/api/store/request/get.md`; docs `content/ja/docs/api/store/request/list.md`; docs `content/ja/docs/api/store/request/customer-uuid.md`; docs `content/ja/docs/api/transactions/request/list.md`; spec `spec/openapi.yaml`; docs `content/ja/docs/api/webhooks/request/get.md`; docs `content/ja/docs/api/webhooks/request/update.md`; docs `content/ja/docs/api/bank-accounts/request/create.md`; docs `content/ja/docs/api/bank-accounts/request/update.md`; docs `content/tested/sandbox-api-behaviour.md`; `getCurrentMerchant.1`)*
- **loud**, -/errors: The webhook list is filtered with active=true or active=false (the filter takes the words active, inactive or all) → 400 "VALIDATION_ERROR (active: INVALID_FORMAT)". **Do:** Send the active filter as active, inactive or all, never as true or false. **Conflict:** The definition types the active filter as a boolean; the tested page shows true and false are refused with 400 VALIDATION_ERROR and the filter takes active, inactive or all; the record follows the tested page. *(docs `content/tested/sandbox-api-behaviour.md`; spec `spec/openapi.yaml`; `listWebhooks.1`)*
- **silent**, state/lists: A webhook is switched off (active false), for example after failed deliveries, or deleted, and the webhook list is read without the active filter, or with active=inactive or active=all → Without the filter (or with active=active) it is left out of the list; with active=inactive or active=all it is listed with active false; GET by its id also returns it. **Do:** To find switched-off or deleted webhooks, list with active=inactive (or all) or GET by the stored id; do not take a missing entry in the default list as proof the webhook is gone. Also: `getWebhook`. *(docs `content/tested/sandbox-api-behaviour.md`; `listWebhooks.2`)*

## `POST /stores/{storeId}/webhooks` (`createWebhook`)

- **loud**, -/errors: A label of the webhook URL's domain (before, between or after the dots) is longer than 63 characters (tested on create with 64 characters) → 400 "VALIDATION_ERROR (url: INVALID_FORMAT_URL)". **Do:** Keep each domain label of the webhook URL at 63 characters or fewer. Also: `updateWebhook`. *(docs `content/ja/docs/guide/detail/webhook.md`; docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.2`)*
- **loud**, -/errors: The webhook `auth_token` (Authorization header value) is shorter than 6 characters (tested on create with 3 characters) → 400 "VALIDATION_ERROR (auth_token: INVALID_FORMAT_LENGTH)". **Do:** Use an auth_token of at least 6 characters. Also: `updateWebhook`. *(docs `content/ja/docs/guide/detail/webhook.md`; docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.3`)*
- **loud**, state/errors: The webhook `url` is already registered for another active webhook in the same scope (tested on create; while the other webhook is switched off or deleted, the same URL is accepted with 201) → 409 "WEBHOOK_URL_EXISTS". **Do:** Add triggers to the existing webhook for that URL instead of creating a second one. Also: `updateWebhook`. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/error/overview.md`; docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.4`)*
- **loud**, limits/errors: The merchant or store already has the maximum number of active webhooks (20); switched-off and deleted webhooks do not count → 400 "RESOURCE_LIMIT_REACHED". **Do:** Reuse an existing webhook, or delete (switch off) ones you no longer need, before 20 are active. **Conflict:** content/ja/docs/api/general/api_limit.md writes the error as `ResourceLimitReached`; the record uses the code from the error table in content/ja/docs/api/error/overview.md. The definition says the limit is on webhooks created per store; the limits page says on active resources, and the tested page agrees (inactive webhooks do not count); the record follows the limits page and the tested page. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/general/api_limit.md`; docs `content/ja/docs/api/error/overview.md`; docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.5`)*
- **loud**, -/errors: A trigger name is not a known event name, e.g. `token_three_d_s_updated` instead of `token_three_ds_updated` → 400 "VALIDATION_ERROR (triggers[0]: INVALID_FORMAT)". **Do:** Use the exact event names, e.g. `token_three_ds_updated`. *(docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.7`)*
- **loud**, -/errors: `triggers` contains an event that is not valid for a store-level webhook → outcome not stated. **Do:** Send only store-level events in triggers. *(spec `spec/openapi.yaml`; `createWebhook.10`)*
- **loud**, auth/-: The request is sent with the app token alone, without its secret (the docs list the secret as required for these calls); tested on GET /me only → 401 Empty body (tested on GET /me). **Do:** Send these calls from your server with `Authorization: Bearer {secret}.{jwt}`, never with the bare app token. Also: `getCurrentMerchant`, `getStore`, `listStores`, `createCustomerId`, `listTransactionHistory`, `listStoreTransactionHistory`, `listWebhooks`, `getWebhook`, `updateWebhook`, `createDirectDebitBankAccount`, `updateDirectDebitBankAccount`. *(docs `content/ja/docs/api/merchant/request/get.md`; docs `content/ja/docs/api/store/request/get.md`; docs `content/ja/docs/api/store/request/list.md`; docs `content/ja/docs/api/store/request/customer-uuid.md`; docs `content/ja/docs/api/transactions/request/list.md`; spec `spec/openapi.yaml`; docs `content/ja/docs/api/webhooks/request/get.md`; docs `content/ja/docs/api/webhooks/request/update.md`; docs `content/ja/docs/api/bank-accounts/request/create.md`; docs `content/ja/docs/api/bank-accounts/request/update.md`; docs `content/tested/sandbox-api-behaviour.md`; `getCurrentMerchant.1`)*
- **silent**, auth/webhooks: A webhook has an `auth_token` set → Each delivery's `Authorization` header is exactly the `auth_token` value, with no `Bearer ` prefix; no signature header is sent. **Do:** Authenticate deliveries by comparing the whole `Authorization` header with the stored `auth_token` (do not expect `Bearer ` or a signature). Also: `background:webhook-delivery`, `updateWebhook`. **Conflict:** The definition calls auth_token a bearer token; the tested page (2026-11-23) saw the raw value with no Bearer prefix. The record follows the tested page. *(docs `content/tested/sandbox-api-behaviour.md`; docs `content/ja/docs/guide/detail/webhook.md`; spec `spec/openapi.yaml`; docs `content/ja/docs/api/webhooks/overview.md`; `background.9`)*
- **silent**, -/errors: The webhook `url` is a local URL such as http://localhost (the docs say local URLs are not allowed); tested on create only → 201 Accepted in test mode; the webhook is created with the local URL. **Do:** Check yourself that the webhook URL is publicly reachable before creating or updating a webhook; the API accepted http://localhost in test mode. Also: `updateWebhook`. **Conflict:** content/ja/docs/api/webhooks/overview.md, request/update.md and guide/detail/webhook.md say local URLs cannot be set, but the tested page saw one accepted on create; the record follows the tested page. *(docs `content/ja/docs/api/webhooks/overview.md`; docs `content/ja/docs/api/webhooks/request/update.md`; docs `content/ja/docs/guide/detail/webhook.md`; docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.1`)*
- **silent**, -/other: `triggers` is sent as an empty list when creating a webhook (the definition says it cannot be empty) → 201 Accepted in test mode; the webhook is created with no triggers. **Do:** Send at least one store-level event in triggers yourself; the API accepted an empty list in test mode. **Conflict:** spec/openapi.yaml says triggers cannot be empty, but the tested page saw an empty list accepted; the record follows the tested page. *(spec `spec/openapi.yaml`; docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.6`)*
- **silent**, -/values: A webhook is created or read with GET → The returned webhook object includes `auth_token` in plain text. **Do:** Treat webhook responses as secret, since they contain the auth token, and don't log them. Also: `getWebhook`. **Conflict:** The GET example in content/ja/docs/api/webhooks/request/get.md shows no auth_token; the record follows the tested page. *(docs `content/tested/sandbox-api-behaviour.md`; `createWebhook.8`)*

## `GET /stores/{storeId}/webhooks/{id}/events` (`listWebhookEvents`)

- **loud**, auth/errors: GET /stores/{storeId}/webhooks/{id}/events is called with a store application token → 401 The response body is empty. **Do:** Don't rely on this endpoint with a store application token; track deliveries on your receiving side. *(docs `content/tested/sandbox-api-behaviour.md`; `listWebhookEvents.1`)*
- **silent**, -/lists: Listing a webhook's events → Each item is one delivery attempt, and `successful` is true only when the receiver answered with HTTP 2xx. **Do:** Expect the same event to appear once per delivery attempt. *(spec `spec/openapi.yaml`; `listWebhookEvents.2`)*
