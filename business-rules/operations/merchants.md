# Merchants

## `GET /me` (`getCurrentMerchant`)

- **loud**, auth/-: The request is sent with the app token alone, without its secret (the docs list the secret as required for these calls); tested on GET /me only → 401 Empty body (tested on GET /me). **Do:** Send these calls from your server with `Authorization: Bearer {secret}.{jwt}`, never with the bare app token. Also: `getStore`, `listStores`, `createCustomerId`, `listTransactionHistory`, `listStoreTransactionHistory`, `listWebhooks`, `createWebhook`, `getWebhook`, `updateWebhook`, `createDirectDebitBankAccount`, `updateDirectDebitBankAccount`. *(docs `content/ja/docs/api/merchant/request/get.md`; docs `content/ja/docs/api/store/request/get.md`; docs `content/ja/docs/api/store/request/list.md`; docs `content/ja/docs/api/store/request/customer-uuid.md`; docs `content/ja/docs/api/transactions/request/list.md`; spec `spec/openapi.yaml`; docs `content/ja/docs/api/webhooks/request/get.md`; docs `content/ja/docs/api/webhooks/request/update.md`; docs `content/ja/docs/api/bank-accounts/request/create.md`; docs `content/ja/docs/api/bank-accounts/request/update.md`; docs `content/tested/sandbox-api-behaviour.md`; `getCurrentMerchant.1`)*
- **silent**, auth/values: GET /me is called (it takes no merchant id; the merchant is resolved from the bearer credentials) → Returns the merchant the credentials belong to; its `id` is the merchantId that other calls use. **Do:** Call GET /me to learn the merchantId for merchant-scoped paths instead of hard-coding it. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/merchant/overview.md`; `getCurrentMerchant.2`)*
- **silent**, account-config/values: Reading the merchant's `configuration` from GET /me → The configuration shown is the default setting for stores created under this merchant. **Do:** Read a store's own settings with GET /stores/{id} instead of assuming the merchant defaults are what the store uses. *(docs `content/ja/docs/api/merchant/overview.md`; `getCurrentMerchant.3`)*
- **silent**, -/values: Reading `configuration.percent_fee` or `configuration.flat_fees` of a merchant or store → The fee values may not exactly reflect the amounts actually used in settlement. **Do:** Do not compute settlement or payout amounts from these fee fields. Also: `getStore`. *(docs `content/ja/docs/api/merchant/overview.md`; docs `content/ja/docs/api/store/overview.md`; `getCurrentMerchant.4`)*
- **silent**, account-config/values: A merchant or store setting such as flat_fees, min_transfer_payout, limit_charge_by_card_configuration or a minimum charge amount is not set → The field is returned as null (GET /stores/{id} also returns minimum_charge_amounts and maximum_charge_amounts as null). **Do:** Parse these setting fields as nullable and treat null as not set. Also: `getStore`. *(docs `content/tested/sandbox-api-behaviour.md`; `getCurrentMerchant.5`)*
