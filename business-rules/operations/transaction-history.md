# Transaction History

## `GET /transaction_history` (`listTransactionHistory`)

- **loud**, auth/-: The request is sent with the app token alone, without its secret (the docs list the secret as required for these calls); tested on GET /me only → 401 Empty body (tested on GET /me). **Do:** Send these calls from your server with `Authorization: Bearer {secret}.{jwt}`, never with the bare app token. Also: `getCurrentMerchant`, `getStore`, `listStores`, `createCustomerId`, `listStoreTransactionHistory`, `listWebhooks`, `createWebhook`, `getWebhook`, `updateWebhook`, `createDirectDebitBankAccount`, `updateDirectDebitBankAccount`. *(docs `content/ja/docs/api/merchant/request/get.md`; docs `content/ja/docs/api/store/request/get.md`; docs `content/ja/docs/api/store/request/list.md`; docs `content/ja/docs/api/store/request/customer-uuid.md`; docs `content/ja/docs/api/transactions/request/list.md`; spec `spec/openapi.yaml`; docs `content/ja/docs/api/webhooks/request/get.md`; docs `content/ja/docs/api/webhooks/request/update.md`; docs `content/ja/docs/api/bank-accounts/request/create.md`; docs `content/ja/docs/api/bank-accounts/request/update.md`; docs `content/tested/sandbox-api-behaviour.md`; `getCurrentMerchant.1`)*
- **loud**, -/errors: `from` is later than `to` → 400 "VALIDATION_ERROR (INCOHERENT_DATE_RANGE)". **Do:** Keep `from` at or before `to`. Also: `listStoreTransactionHistory`. *(spec `spec/openapi.yaml`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.5`)*
- **loud**, -/errors: `short_id` is not exactly 6 characters (the last 6 characters of the charge or refund UUID); tested with 5 characters → 400 "VALIDATION_ERROR (short_id: INVALID_FORMAT)". **Do:** Send short_id as exactly the last 6 characters of the charge or refund UUID. Also: `listStoreTransactionHistory`. *(spec `spec/openapi.yaml`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.6`)*
- **loud**, -/errors: `card_last_four` is not exactly 4 characters (tested with 3 characters) → 400 "VALIDATION_ERROR (card_last_four: INVALID_FORMAT_LENGTH, INVALID_FORMAT)". **Do:** Send card_last_four as exactly 4 characters. Also: `listStoreTransactionHistory`. *(spec `spec/openapi.yaml`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.7`)*
- **loud**, -/errors: Transaction history is filtered with status=errored (the value the transactions overview page lists) → 400 "VALIDATION_ERROR (status: INVALID_FORMAT)". **Do:** Filter with status=error, not errored. Also: `listStoreTransactionHistory`. **Conflict:** content/ja/docs/api/transactions/overview.md lists `errored`, but the tested page saw it refused; the record follows the tested page. *(docs `content/tested/sandbox-api-behaviour.md`; docs `content/ja/docs/api/transactions/overview.md`; `listTransactionHistory.13`)*
- **silent**, other/lists: Reading a resource's current state from a LIST response → The list is not strictly real-time and may lag slightly behind the actual data. **Do:** Confirm the latest state of a single resource with its GET call, not with the list. Also: `listStores`, `listStoreTransactionHistory`. *(docs `content/ja/docs/api/store/request/list.md`; docs `content/ja/docs/api/transactions/request/list.md`; `listStores.2`)*
- **silent**, -/lists: GET /transaction_history is called (no store in the path) → Charges and refunds of all the merchant's stores are returned together in one row format. **Do:** Use GET /stores/{storeId}/transaction_history when you need one store only. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/transactions/request/list.md`; `listTransactionHistory.1`)*
- **silent**, -/lists: Paging through transaction history → `total_hits` is included only on the first page (no cursor) or the last page, and `next_cursor` only while `has_more` is true. **Do:** Read total_hits from the first page and pass next_cursor as cursor until has_more is false. Also: `listStoreTransactionHistory`. *(spec `spec/openapi.yaml`; `listTransactionHistory.2`)*
- **silent**, -/lists: Several filter parameters are given in one transaction history request → All filters are combined with AND. **Do:** Expect each extra filter to narrow the results. Also: `listStoreTransactionHistory`. *(docs `content/ja/docs/api/transactions/request/list.md`; `listTransactionHistory.3`)*
- **silent**, -/lists: An array filter (`brand[]`, `service_providers[]`, `bank_transfer_payment_statuses[]`) is repeated with several values → The values of that one filter are combined with OR. **Do:** Repeat an array filter to widen the match within that filter. Also: `listStoreTransactionHistory`. *(spec `spec/openapi.yaml`; `listTransactionHistory.4`)*
- **silent**, -/lists: Filtering with `search`: the definition says it matches cardholder or customer names and email addresses, the docs say it also matches charge ID, refund ID, metadata and the card's last four digits, but in the test a full charge ID returned one item that was not that charge → 200 A search for a full charge ID returned one item, which was not that charge. **Do:** Use the dedicated filters (id, metadata, card_last_four, email) for those values, and never use search to find a charge by its ID. Also: `listStoreTransactionHistory`. **Conflict:** content/ja/docs/api/transactions/request/list.md says search matches charge IDs, but the tested page saw a full charge ID return another charge, so the record follows the tested page for charge IDs; for refund IDs, metadata and card digits the definition and the docs still disagree (untested). *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/transactions/request/list.md`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.8`)*
- **silent**, -/lists: A `search` or `cardholder` value is wrapped in double quotes → The value is matched as an exact phrase; without quotes the match is partial. **Do:** Wrap the value in double quotes when you need an exact name match. Also: `listStoreTransactionHistory`. *(spec `spec/openapi.yaml`; `listTransactionHistory.9`)*
- **silent**, -/values: Filtering on or reading `status` in transaction history: the value is `error` (status=error returns 200), not `errored` as the transactions overview page lists → Charge and refund statuses can both be used as filters; refund rows only report pending, successful, failed or error. **Do:** Use `error`, not `errored`, as the status value, and accept only pending, successful, failed or error on refund rows. Also: `listStoreTransactionHistory`. **Conflict:** content/ja/docs/api/transactions/overview.md lists `errored`; the definition and the tested page use `error`; the record follows the tested page. *(spec `spec/openapi.yaml`; docs `content/ja/docs/api/transactions/overview.md`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.10`)*
- **silent**, auth/-: Filtering with `mode=live_test` with a store application token (the definition reserves live_test for privileged callers) → 200 Accepted in test mode with a store application token; no error is returned. **Do:** Filter with `live` or `test` only, and do not rely on the API to refuse `live_test`; it returned 200 for a store application token in test mode. Also: `listStoreTransactionHistory`. **Conflict:** spec/openapi.yaml reserves live_test for privileged callers, but the tested page saw a store application token accepted; the record follows the tested page. *(spec `spec/openapi.yaml`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.11`)*
- **silent**, -/lists: `service_providers[]` is sent empty → 200 Accepted in test mode; no error is returned. **Do:** Leave service_providers[] out instead of sending it empty; the API accepted an empty value in test mode, so do not rely on it to refuse one. Also: `listStoreTransactionHistory`. **Conflict:** spec/openapi.yaml says service_providers[] cannot be empty, but the tested page saw an empty value return 200; the record follows the tested page. *(spec `spec/openapi.yaml`; docs `content/tested/sandbox-api-behaviour.md`; `listTransactionHistory.12`)*
